# Модуль 01 — Создавай сайты, видео и 3D-анимацию с помощью нейросетей

Один модуль, 28 уроков подряд — от настройки инструментов до первых денег. Деловой стиль, без
разжёвывания азов, сразу формулы/действия/результат. Сквозной рабочий пример через весь курс —
сам сайт NEURA и материалы его продвижения (index.html, style.css, script.js из репозитория),
поэтому каждый приём сразу виден на реальном, а не абстрактном проекте. Курс построен вокруг
Claude как основного текстового инструмента — с использованием его реальных возможностей
(Projects, Skills, коннекторы), а не только голого чата.

Уроки идут шестью тематическими этапами, но это один непрерывный путь: каждый следующий урок
опирается на результат предыдущего, порядок не пропускается.

## Содержание

1. Основы работы с нейросетями — уроки 1–4
2. Сайт с нуля — уроки 5–9
3. Генерация изображений — уроки 10–14
4. Видео и оживление кадров — уроки 15–19
5. 3D-сцены и анимация — уроки 20–23
6. Упаковка под площадки — уроки 24–28

---

## Этап 1. Основы работы с нейросетями (уроки 1–4)

Этап ставит рабочий инструментарий и один ключевой навык — формулировать запрос так, чтобы
получать нужный результат с первого-второго раза, а не перебирать варианты вслепую.

### Урок 1. Карта инструментов и честный доступ

**Цель:** понимать, какая нейросеть закрывает какую задачу курса, как настроить Claude под работу
над проектом (а не использовать голый чат), какой бюджет закладывать отдельно от цены курса, и
как оплатить/открыть доступ из Казахстана — до того, как это станет проблемой на уроке 10.

#### Инструменты курса и их роль

| Нейросеть | Задача | Уроки |
|---|---|---|
| Claude | Тексты, брифы, продюсирование проекта, постановка задач другим нейросетям | Все уроки |
| Midjourney / Stable Diffusion | Генерация изображений | 7, 10–14 |
| Sora / Veo / Kling / Runway / Higgsfield | Генерация и оживление видео | 15–19 |
| Image-to-3D + Blender | 3D-объекты и сцены | 20–23 |

Конвейер курса: идея → текст (Claude) → изображение (Midjourney) → сайт **или** видео/3D →
упаковка под площадку. Каждый этап опирается на результат предыдущего — пропускать не стоит.

Midjourney vs Stable Diffusion: Midjourney даёт стабильно качественный результат из коробки, но
без бесплатного тарифа. Stable Diffusion сложнее в настройке, зато есть бесплатные варианты
запуска. Для старта курса рекомендуем Midjourney — ниже порог входа, быстрее первый результат.

#### Настройка Claude под курс: Projects, Skills, коннекторы

Прежде чем писать первый промпт, стоит настроить сам Claude — три встроенных механизма экономят
часы уже начиная с урока 5, и переиспользуются во всём курсе.

**Projects (проекты).** Отдельный проект под каждую крупную задачу курса (сайт, ролик, 3D-объект)
вместо одного длинного чата обо всём. В проект добавляются инструкции (аудитория, цель, тон —
то, что раньше называлось «мастер-промпт») и файлы (бриф, мудборд, референсы). Claude держит это
в контексте во всех чатах внутри проекта — не нужно каждый раз объяснять заново. Подробно
разбирается в уроке 3.

**Skills (навыки).** Пакет инструкций, который Claude применяет автоматически, когда задача под
него подходит. Есть встроенные Skills (например, для работы с документами, таблицами,
презентациями — пригодятся на последнем этапе, уроки 24–28, для контент-плана и коммерческого
предложения), их можно включить в настройках аккаунта. Есть возможность собрать свой собственный
Skill — для курса самый полезный пример — «голос бренда»: один раз описываете тон, структуру
блоков, стилевые слова (после урока 5), и дальше Claude применяет это в каждом новом тексте без
повторного объяснения. Собираем свой Skill в уроке 6.

**Коннекторы.** Прямое подключение Claude к внешним сервисам без ручного копирования файлов
туда-обратно: Google Drive/Docs — для хранения брифов, мудборда и личной базы промптов (урок 4);
GitHub — для публикации сайта (урок 9). Настраиваются один раз в настройках аккаунта, раздел
Connectors, дальше Claude читает и сохраняет файлы в подключённый сервис прямо по команде в чате.

**Действие:**
1. В настройках аккаунта Claude открыть раздел Skills, посмотреть встроенные — включить те, что
   пригодятся под задачи курса (документы/таблицы).
2. Подключить коннектор Google Drive (или аналогичное облачное хранилище, которым пользуетесь) —
   туда пойдёт личная база из урока 4.
3. Подключить коннектор GitHub — понадобится в уроке 9. Если ещё не пользовались GitHub — можно
   отложить этот пункт до конца этапа «Сайт», но лучше настроить сразу, пока внимание на
   настройках.
4. Создать первый Project в Claude под текущую задачу («Сайт NEURA» или свой проект) — пустой,
   без инструкций, наполнение будет в уроке 3.

**Типичная ошибка:** подключать сразу все доступные Skills и коннекторы «про запас» — как и с
самими нейросетями (см. таблицу ниже), включаем только то, что реально нужно под ближайший урок.

#### Бюджет на инструменты — отдельно от цены курса

| Нейросеть | Бесплатного тарифа достаточно для обучения? | Когда понадобится платный |
|---|---|---|
| Claude | Да, на большую часть курса | Для более мощной модели и большего лимита запросов |
| Midjourney | Нет | С первого дня урока 10 |
| Stable Diffusion | Да (сложнее в настройке) | Для скорости и удобства |
| Kling / Runway / Sora / Veo / Higgsfield | Ограниченно, для проб | Как только нужен объём больше пары роликов в месяц |
| Blender | Полностью бесплатен | Никогда |

Открывайте платный тариф точечно, под конкретный урок — не оплачивайте всё в первую неделю.

#### Доступ из Казахстана

Три момента, которые снимают 90% проблем с доступом:

1. **Оплата картой.** Часть сервисов принимает карты KZ напрямую — проверяется на странице
   тарифов конкретного сервиса (актуальный список быстро меняется, фиксировать его здесь смысла
   нет). Если карта не проходит — виртуальная карта для оплаты зарубежных подписок закрывает
   почти все случаи.
2. **Доступ к самому сервису.** Отдельная история от оплаты: если сервис не открывается из
   региона совсем, нужен VPN для работы, а не только для разовой оплаты.
3. **Порядок действий:** сначала проверяете конкретный сервис перед стартом нужного урока, а не
   разбираетесь со всеми сразу в первую неделю.

#### Действие

1. Зарегистрировать аккаунт Claude и пройти настройку из раздела выше (Skills, коннекторы, первый
   Project).
2. Выбрать картиночную нейросеть под урок 10 (по умолчанию — Midjourney) и проверить способ
   оплаты под свою карту заранее.
3. Видео и 3D-инструменты не трогать — к ним переходите на уроках 15–23.

**Типичная ошибка:** открывать и оплачивать все восемь инструментов сразу «про запас» — деньги
на подписки, которыми не пользуетесь месяцами.

→ **Результат:** схема «инструмент → задача» + чек-лист доступа (оплачено / бесплатно / нужно
сделать до урока 5) + настроенный Claude (Skills включены, коннекторы Google Drive и GitHub
подключены, первый Project создан).

### Урок 2. Анатомия промпта

**Цель:** собирать запрос по формуле, а не наугад — с первого-второго раза получать нужный
результат вместо десятков попыток.

#### Формула

**Субъект → действие/состояние → стиль → свет и камера → референс → что убрать.**

Используются не все шесть частей в каждом промпте — но чем важнее результат, тем больше частей
стоит закрыть явно, не оставляя на додумывание нейросети.

#### Пример: разница на одной задаче

**Слабо:** «красивый сайт про кофе» — нейросеть додумывает аудиторию, стиль, настроение сама, и
почти всегда не так, как задумано.

**По формуле:** «Главный экран сайта кофейни в спальном районе (субъект). Бариста готовит
капучино за стойкой (действие). Тёплый, домашний стиль, минимум глянца — как в инстаграме
локальной кофейни, не сетевого фастфуда (стиль/референс). Мягкий естественный свет из окна
слева, кадр на уровне стойки (свет и камера). Без текста и логотипов на изображении, без людей
на фоне за окном (что убрать)».

Разница видна ещё до генерации: во втором случае нейросети не из чего додумывать за вас.

#### Практика

Одна идея → три версии: короткая строка без формулы, средняя (субъект + действие + стиль),
полная (все шесть частей). Сравнить результат генерации по каждой — это даёт наглядное понимание,
где проходит граница между «додумано неверно» и «готово с первого раза».

**Частые ошибки:**
- Копировать чужой промпт без понимания структуры — при смене темы результат разваливается.
- Пытаться закрыть всё одним промптом вместо того, чтобы сначала получить базу, потом уточнить.
- Пропускать «что убрать» — именно эта часть чаще всего отсекает случайные лишние детали.

**Отладка:** если результат не тот — меняйте одну часть формулы за раз и сравнивайте, а не всё
сразу. Так видно, какая часть за что отвечает.

→ **Результат:** 10 промптов по формуле, зафиксированных вместе с результатом генерации.

### Урок 3. Claude как продюсер проекта

**Цель:** использовать Claude не для разовых текстов, а как инструмент, который держит контекст
всего проекта через Projects и ставит задачи другим нейросетям — экономия часов начиная с
урока 5.

#### Действие

1. **Одна крупная задача курса — один Project в Claude**, не бесконечный общий чат обо всём.
   Проект, созданный в уроке 1, наполняется здесь: инструкции и файлы держат контекст во всех
   чатах внутри него, не только в одном диалоге.
2. **Мастер-промпт → инструкции проекта.** То, что раньше писалось первым сообщением в чат,
   теперь идёт в поле инструкций самого Project — задаётся один раз и применяется автоматически
   в каждом новом чате внутри проекта. Пример инструкции: «Веди меня как продюсер проекта. Делаю
   сайт-визитку для мастера маникюра в Алматы, аудитория — женщины 20–40 лет, тон дружелюбный, без
   канцелярита. Дальше буду просить тексты, структуру и промпты для картинок под этот проект —
   держи контекст во всех ответах».
3. **Бриф вместо прямого запроса.** Не «сделай текст для сайта», а «сначала задай мне 5 вопросов,
   которые нужны, чтобы написать хорошо» — результат стабильно точнее прямого запроса без брифа.
4. **Постановка задач другим нейросетям.** Сцену для Midjourney/Kling описываете Claude своими
   словами и просите оформить в промпт по формуле из урока 2, дорабатываете под себя.
5. **Файлы проекта через коннектор.** Если в уроке 1 подключён Google Drive — референсы и бриф
   можно держать прямо в подключённой папке, Claude обращается к ним по команде в чате, без
   ручной загрузки каждого файла заново.

**Частые ошибки:**
- Общий чат без Project под каждую мелочь — теряется контекст, задача решается медленнее.
- Запрос без брифа («сделай крутой сайт») — на выходе усреднённый, обезличенный результат.
- Инструкции проекта написаны один раз и никогда не обновляются — если бриф меняется по ходу
  работы (например, после урока 5), инструкции стоит обновить, иначе Claude держит устаревший
  контекст.

→ **Результат:** настроенный Project (инструкции + файлы) для текущей задачи + два готовых брифа
(сайт, видеоролик), которые можно применить к новым проектам дальше по курсу.

### Урок 4. Библиотека промптов и референсов

**Цель:** система хранения, которая исключает повторное изобретение того, что уже сработало —
пополняется на каждом следующем этапе без перестройки структуры.

#### Структура

Три раздела: **промпты / референсы / готовые файлы**. Если в уроке 1 подключён коннектор
Google Drive — это те же три раздела прямо в подключённой папке, и Claude может доставать из них
нужное по команде в чате, а не только вы вручную. Если коннектор не подключён — подходит любой
формат хранения (заметки, документ), принципиальна структура, а не инструмент.

**Правило отбора:** в библиотеку идёт только рабочее, с короткой пометкой почему сработало
(«мягкий свет + вид сбоку — передаёт уют»). Эта пометка экономит время больше, чем сам промпт.

**Референс-борд** — чужие примеры по стилю, не для копирования, а как ориентир по свету/цвету/
настроению.

#### Действие

Перенести промпты из уроков 2–3 в структуру выше — это стартовая версия личной базы.

**Частые ошибки:**
- Промпты вперемешку с перепиской — через месяц не найти нужный.
- Сохранён результат без промпта, которым он получен — теряется воспроизводимость.

→ **Результат:** личная база промптов (10+ позиций из уроков 2–3, разложенных по разделам, по
возможности — в подключённом через коннектор хранилище).

### Промежуточный итог (после урока 4)

К этому моменту должно быть готово:

- настроенный Claude: включённые Skills, подключённые коннекторы (Google Drive, GitHub), первый
  Project с инструкциями и файлами; выбранная и оплаченная (или отмеченная к оплате) картиночная
  нейросеть под урок 10;
- 10 промптов по формуле из урока 2;
- Project с инструкциями-«мастер-промптом» и два готовых брифа (сайт, видео) из урока 3;
- личная база промптов, разложенная по разделам, готовая пополняться дальше.

Следующий этап («Сайт с нуля», уроки 5–9) опирается на весь этот набор без повторного
объяснения — если какой-то пункт не закрыт, имеет смысл вернуться к нему до старта урока 5.

## Этап 2. Сайт с нуля (уроки 5–9)

Этап ведёт от идеи до опубликованной страницы. В качестве рабочего примера используется сам сайт
NEURA (`index.html`, `style.css`, `script.js` из репозитория курса) — вы видите не абстрактный
«сайт про кофе», а реальный лендинг с реальной структурой, реальными текстами и реальным кодом,
который уже работает и продаёт. Это и есть эталон, к которому приводится ваш собственный проект.

### Урок 5. Планирование: зачем сайт и кому

**Цель:** зафиксировать структуру, цель и УТП до генерации текста и визуала — иначе уроки 6–8
превращаются в переделки.

#### Разбор структуры NEURA как эталона

Сайт NEURA — лендинг под продукт (курс), не визитка и не портфолио. Его структура:

1. **Hero** (`.hero`) — оффер в заголовке, буллеты миссии, кнопки «Тарифы» / «Программа». Задача
   блока — за 5 секунд ответить «что это и зачем мне».
2. **Чему учим** (`.item` карточки) — три конкретных навыка, а не абстрактное «научим нейросетям».
3. **Программа** (`.mods`, аккордеон) — детализация без перегрузки: свёрнутые блоки, разворачивает
   только тот, кому интересно.
4. **Тарифы** (`#pricing`, `.plan` карточки) — три варианта, средний выделен как «Полный доступ»
   (`.plan--full`) — классический приём: не выбирать между «купить/не купить», а между вариантами
   покупки.
5. **FAQ** (`.acc`) — снимает возражения до того, как они приведут к отказу от покупки.
6. **Футер** — юридика (оферта, политика), не потерянная информация о доступности.

Это и есть шаблон структуры блоков для лендинга под продукт/услугу: оффер → польза → детали →
цена → снятие возражений → доверие/юридика.

#### Действие

1. Определить тип страницы под свою задачу (визитка / портфолио / лендинг под продукт) — у
   каждого своя структура блоков, не универсальный шаблон.
2. Разобрать 2–3 чужих сайта в своей нише на сильные/слабые места по той же логике, что выше:
   что цепляет в первые секунды, где теряется посетитель.
3. Сформулировать УТП — без него генерация текста в уроке 6 даст общие фразы вместо продающих.
4. Собрать структуру блоков своего сайта по аналогии с NEURA, адаптировав под свою задачу (не
   каждому нужны все шесть блоков — например, визитке не нужны тарифы).

**Типичная ошибка:** начинать с визуала до того, как определена структура и цель — переделки на
этом этапе дороже, чем на этапе брифа.

→ **Результат:** бриф сайта — структура блоков + цель + аудитория + УТП.

### Урок 6. Тексты для сайта через нейросеть

**Цель:** тексты по каждому блоку, которые не считываются как сгенерированные.

#### Разбор на примере NEURA

Заголовок hero-блока NEURA — «Создавай сайты, видео и 3D-анимацию с помощью нейросетей» — прямой,
без метафор, сразу называет результат. Подзаголовок расшифровывает через ограничение: «Курс для
тех, у кого есть базовые знания компьютера. Без кода и команды — только вы и нейросети». Это
снимает главное возражение аудитории («я не программист») в одном предложении.

Формула, по которой это собрано: **роль аудитории → результат → снятое возражение**. Работает не
только для курсов — для любого лендинга под продукт/услугу.

#### Действие

1. Промпт-формула для текста блока: роль аудитории + бриф из урока 5 + тон + ограничение по
   длине — с опорой на инструкции Project, заданные в уроке 3.
2. Генерация по блокам отдельно (заголовок, оффер, польза, о себе/продукте, призыв к действию) —
   не весь текст сайта одним запросом, иначе тон плывёт между блоками.
3. Редактура: убрать типовые AI-обороты («в современном мире», «мы рады предложить») и подогнать
   под собственный голос бренда.
4. Сверка каждого текста с УТП из брифа — текст должен продавать конкретное отличие, а не общие
   слова.

**Типичная ошибка:** публиковать первый сгенерированный вариант без редактуры — «сгенерированный»
тон считывается посетителем моментально и снижает доверие.

#### Голос бренда как Skill

Как только тон и формулировки для блоков устоялись (готовы, вас устраивает результат) — оформите
это отдельным Skill (см. урок 1): 3–5 примеров текста + короткое описание тона и ограничений
(«без канцелярита», «короткие предложения», «конкретика вместо общих слов»). Дальше этот Skill
подключается к Project — и любой новый текст (в этом же проекте или в следующем) сразу выходит в
нужном голосе, без повторной настройки в каждом запросе.

→ **Результат:** готовые тексты всех блоков сайта + Skill «голос бренда» для переиспользования.

### Урок 7. Визуал сайта

**Цель:** единый визуальный стиль на палитре и одном подходе к генерации — не набор случайных
картинок.

#### Разбор на примере NEURA

Визуальный код NEURA держится на трёх решениях, зафиксированных в `style.css`:

- **Палитра** — тёмный индиго-фон, неоново-бирюзовый акцент (`--g`), розовый и фиолетовый как
  вторичные акценты (`--pink`, `--violet`). Три акцентных цвета, не больше — иначе палитра
  рассыпается.
- **Типографика** — моноширинный шрифт для лейблов/меток (`--mono`), обычный узкий шрифт для
  заголовков. Комбинация «технично + человечно», которая соответствует теме курса.
- **Атмосфера фона** — анимированный «дождь» символов (`#rain`, `#tunnel`), приглушённый затемнением
  по центру (`.scrim`), чтобы не спорить с текстом. Фон работает на настроение, но не мешает читать.

Принцип, который переносится на любой проект: сначала фиксируется палитра (3–5 цветов) и один
стилевой ориентир, потом под них генерируется всё остальное — а не наоборот.

#### Действие

1. Выбрать направление стиля под тему сайта до начала генерации, не после.
2. Промпты для изображений блока по формуле из урока 2, с единым набором стилевых слов на весь
   проект — иначе визуал расходится по стилю от блока к блоку.
3. Собрать палитру (3–5 цветов) и шрифтовую пару на основе главного визуала.
4. Иконки и мелкие элементы — где оправдана генерация, а где быстрее взять готовый набор.

**Типичная ошибка:** генерировать каждое изображение с новым промптом без переиспользования
стилевых слов — визуал сайта расползается по стилю от блока к блоку.

→ **Результат:** набор визуалов + палитра + шрифтовая пара проекта.

### Урок 8. Сборка страницы

**Цель:** собрать тексты и визуал из уроков 6–7 в рабочую страницу, корректную на телефоне — без
редактора кода, прямо в диалоге с Claude.

#### Сборка через Artifacts

Claude умеет не просто описывать код страницы, а собирать и сразу показывать её рядом с чатом —
это и есть Artifacts: живой предпросмотр, который обновляется по мере правок. Для сайта на
no-code это ключевой рабочий режим этапа: не «скопировать код себе и открыть отдельно», а
смотреть готовую страницу сразу в диалоге и просить точечные изменения («сделай кнопку крупнее»,
«подвинь блок тарифов выше») так же, как обсуждали бы это с дизайнером.

#### Действие

1. Сборка внутри Project из урока 3: структура блоков (из урока 5) и контент (уроки 6–7)
   подаются частями, не всё сразу одним запросом — так проще указывать точечные правки по ходу.
2. Просить Artifact на каждый крупный блок или сразу на всю структуру — зависит от объёма, но
   проверка результата идёт сразу в предпросмотре, не после «отправки в работу».
3. Проверка адаптива после каждого собранного блока, не в конце — на NEURA это заметно по
   `@media (max-width:900px)` в `style.css`: бургер-меню вместо навигации, карточки тарифов в
   один столбец вместо трёх. В Artifact-предпросмотре это видно сразу же по запросу «покажи, как
   это выглядит на телефоне».
4. Базовая анимация — на NEURA это плавное появление блоков при скролле (`.up` / `.up.in`) и
   реакция кнопок на наведение. Анимация ведёт взгляд к цели, не отвлекает от текста.
5. Сверка с брифом урока 5: каждый блок структуры на месте, УТП считывается в первые секунды.

**Типичная ошибка:** проверять адаптив только после полной сборки страницы — переделки на этом
этапе обходятся дороже, чем проверка по ходу, а в Artifacts эта проверка ничего не стоит —
достаточно попросить.

→ **Результат:** рабочая версия сайта в виде Artifact, готовая к публикации.

### Урок 9. Публикация

**Цель:** сайт доступен по рабочей ссылке, с пониманием стоимости хостинга/домена и без потери
рабочей копии при обновлении.

#### Два пути публикации

**Быстрый путь** — публикация Artifact напрямую из Claude: подходит для портфолио и черновой
проверки на реальных посетителях, без отдельного хостинга и домена.

**Полноценный путь** — через коннектор GitHub из урока 1: Claude выгружает код страницы в ваш
репозиторий, дальше репозиторий подключается к хостингу с собственным доменом (например, тем же
способом, каким размещён сам сайт NEURA). Этот путь нужен, если сайт делается под клиента или как
постоянный проект, а не как учебный черновик.

#### Действие

1. Выбор пути под задачу: быстрый (Artifact) для портфолио/черновика vs через GitHub-коннектор +
   свой хостинг и домен для проекта под клиента — с чётким пониманием, что теряется на быстром
   пути (нет своего домена, ограниченный контроль над хостингом).
2. При выборе полноценного пути — выгрузка через коннектор GitHub, привязка домена, с поправкой на
   типичное время обновления DNS, чтобы отсутствие сайта в первые минуты не воспринималось как
   ошибка.
3. Публикация и проверка по чек-листу: открывается с телефона, все ссылки и кнопки рабочие, формы
   отправляются.
4. Разбор типичных ошибок первого запуска: битые пути к изображениям, забытые тестовые тексты,
   отсутствие HTTPS.

**Типичная ошибка:** публиковать без финальной проверки на реальном телефоне, а не только в
браузере на компьютере.

→ **Результат:** сайт, доступный по ссылке в интернете.

**Итог этапа «Сайт» (тариф «Сайты», уроки 1–9):** опубликованный сайт + личная база промптов и
шаблонов для сайтов.

## Этап 3. Генерация изображений (уроки 10–14)

Единый узнаваемый визуал для любого проекта — от обложки до кадра в ролике. Рабочий пример —
визуальный ряд бренда NEURA: тёмный индиго-фон, неоново-бирюзовый акцент, розовый/фиолетовый как
вторичные цвета (палитра `style.css`), минимализм без глянца. Результат этапа — мудборд, который
затем используется как основа уроков 15–23.

### Урок 10. Основы Midjourney / Stable Diffusion

**Цель:** уверенно управлять базовыми параметрами генерации вместо расчёта на удачу с первого
раза.

#### Действие

1. Разница инструментов: Midjourney — быстрый стабильный результат из коробки, платный без
   бесплатного тарифа; Stable Diffusion — больше контроля, есть бесплатные пути запуска, выше
   порог входа. Выбор под задачу, не «один инструмент навсегда».
2. Ключевые параметры: соотношение сторон под задачу (обложка ролика — 9:16, изображение для
   сайта — свободнее, зависит от блока), версия модели, базовые флаги качества/стиля.
3. Практика «6 вариаций одного промпта» — смена одного параметра за раз (соотношение сторон,
   версия модели), чтобы видеть, что конкретно на что влияет.
4. Отбор и организация результата сразу по папке проекта из урока 4, без накопления лишнего.

**Типичная ошибка:** менять сразу несколько параметров одновременно — непонятно, что именно
повлияло на результат.

→ **Результат:** 20 изображений в едином стиле (палитра/настроение NEURA).

### Урок 11. Композиция, свет, ракурс

**Цель:** управлять кадром через промпт осознанно, не перебором вариантов.

#### Действие

1. Правило третей и композиционный центр — как задать словами, куда должен смотреть глаз.
2. Свет как инструмент настроения: для стиля NEURA — холодный неоновый контровой/боковой свет
   против тёмного фона, а не мягкий тёплый (который сработал бы для другой ниши, например, уюта
   кофейни). Разбор одного сюжета в разном свете показывает разницу настроения напрямую.
3. Ракурс и оптика: уровень глаз, снизу, сверху, широкий угол vs портретный объектив — конкретные
   формулировки в промпте вместо «красиво».
4. Сборка сюжета под конкретную эмоцию (для NEURA — «технологичность и уверенность») через
   сочетание композиции, света и ракурса.

**Типичная ошибка:** описывать свет прилагательным «красивый» без конкретики — нейросети нужна
формулировка (например, «холодный контровой неоновый свет»), а не оценка.

→ **Результат:** серия из 5 изображений с разной постановкой света на один сюжет.

### Урок 12. Консистентность персонажа/объекта

**Цель:** решить главную практическую проблему генерации — объект/персонаж не «расползается» по
внешности от сцены к сцене.

#### Действие

1. Разбор причины: у нейросети нет «памяти» между генерациями по умолчанию — консистентность
   достигается техниками (референс-изображение, seed, детальное фиксированное описание).
2. Сборка «паспорта» объекта — фиксированного набора признаков, повторяемых в промпте каждой новой
   сцены дословно. Для NEURA это, например, фирменный геометрический элемент/иконка: форма, цвет,
   толщина линий, свечение — фиксируются один раз и переносятся без изменений.
3. Практика: один и тот же объект в 4 разных сценах (разный фон, ракурс, свет) с проверкой на
   совпадение ключевых признаков.
4. Если объект «уехал» по внешности — точечная правка через референс, не перегенерация с нуля.

**Типичная ошибка:** менять формулировку описания объекта между сценами «для разнообразия» — это
и есть причина расползания.

→ **Результат:** 1 объект в 4 разных сценах без расползания внешности.

### Урок 13. Редактура и апскейл

**Цель:** точечно исправлять и увеличивать готовое изображение, не перегенерируя всё с нуля.

#### Действие

1. Локальные правки (inpainting): переделка только выделенной области, остальное изображение не
   трогается.
2. Апскейл под задачу: компактно и быстро для сайта (веб-версия) vs максимальное качество для
   обложки/печати.
3. Устранение типичных артефактов генерации — какие правятся inpainting, какие быстрее
   перегенерировать целиком.
4. Сравнение «до/после» — оценка, действительно ли правка улучшила результат.

**Типичная ошибка:** апскейл до внесения всех правок — апскейл выполняется последним шагом.

→ **Результат:** 3 изображения «до/после» правки.

### Урок 14. Мудборд проекта

**Цель:** собрать визуальный язык, который станет основой для видео (уроки 15–19) и 3D (уроки
20–23) — единый проект, не три разных.

#### Действие

1. Отбор лучших результатов уроков 10–13 по единой логике (совпадение по свету/цвету/настроению,
   не «что понравилось» по отдельности).
2. Сборка палитры и типографики на основе отобранных изображений — для NEURA это фиксация того
   же принципа, что уже задан в `style.css`: 3 акцентных цвета, моноширинный шрифт для меток.
3. Референс-борд с пометками: что берётся в видео (ракурсы, свет), что — в 3D (формы, материалы).
4. Проверка «на один взгляд»: узнаваем ли стиль за 2 секунды без подписей.

**Типичная ошибка:** собирать мудборд после начала работы над видео/3D, а не до — стиль
расползается уже на старте урока 15.

→ **Результат:** мудборд — основа для уроков 15–23.

## Этап 4. Видео и оживление кадров (уроки 15–19)

Путь от идеи до смонтированного ролика. Рабочий пример — рекламный ролик для курса NEURA (тот
самый продукт, сайт которого собирался на этапе 2): 15–20 секунд, вертикальный формат, задача —
та же, что у hero-блока сайта: за несколько секунд объяснить, что это и зачем. Стиль ролика
опирается на мудборд уроков 10–14 (тёмный фон, неоновый акцент, минимализм). Видео — отдельная
крупная задача, значит отдельный Project в Claude (см. урок 3): подключите к нему Skill «голос
бренда» из урока 6 — сценарий и подписи сразу выйдут в том же тоне, что и тексты сайта.

### Урок 15. Text-to-video

**Цель:** реалистично оценивать, что получается генерацией с нуля с первого-второго раза, а что
добирается монтажом — без лишних генераций впустую.

#### Разбор на примере

Сцена для ролика NEURA: «крупный план рук за клавиатурой, на экране монитора появляется
интерфейс сайта, неоновая подсветка на клавиатуре». Промпт по формуле из урока 2: субъект
(руки за клавиатурой) → действие (набор текста, на экране проступает интерфейс) → стиль (тёмный,
неоновый, техно-эстетика — как в мудборде уроков 10–14) → свет и камера (крупный план, холодный
неоновый свет сбоку) → референс (в духе рекламы IT-продуктов) → что убрать (без лишних людей и
предметов в кадре).

#### Действие

1. Обзор инструментов (Sora, Veo, Kling, Runway, Higgsfield) — у каждого свои сильные стороны
   (динамика камеры, реализм, длина клипа). Выбор под конкретную сцену, не «один инструмент на
   всё».
2. Промпт для видео поверх формулы из урока 2, с добавлением тайминга действия (что происходит
   по секундам) и характера движения камеры.
3. Практика: одна сцена — 3 версии с разными настройками движения/длины, сравнение результата.
4. Граница возможностей: сложная физика, много персонажей в кадре, читаемый текст в кадре —
   зоны нестабильного результата. Обходятся монтажным решением (склейка простых клипов), а не
   попыткой получить всё одним промптом.
5. Версии инструментов меняются быстро — формула промпта (структура) остаётся рабочей при смене
   версии, конкретные параметры/флаги проверяются каждый раз заново.

**Типичная ошибка:** попытка получить длинную сложную сцену одним промптом вместо нескольких
коротких клипов, склеенных в уроке 17.

→ **Результат:** 3 коротких сгенерированных клипа.

### Урок 16. Image-to-video: оживление

**Цель:** оживить статичные изображения из этапа 3 вместо генерации видео с нуля — использовать
уже согласованный по стилю визуал.

#### Действие

1. Разница подходов: лёгкое движение камеры (парящий эффект) vs анимация объектов внутри кадра —
   выбор под тип изображения.
2. Оживление изображений с сохранением консистентности, настроенной в уроке 12 (для ролика
   NEURA — например, логотип или ключевой визуальный элемент, повторяющийся в кадре).
3. Зацикливание (loop) — бесшовное короткое движение для фоновых кадров/обложки.
4. Отбор кадров под оживление: простая композиция даёт предсказуемый результат, перегруженная —
   нет.

**Типичная ошибка:** оживлять изображение с мелким текстом/деталями — при анимации такие детали
чаще всего искажаются.

→ **Результат:** 3 «оживлённых» кадра.

### Урок 17. Монтаж и склейка

**Цель:** собрать клипы из уроков 15–16 в ролик с осмысленным темпом, а не нарезку подряд.

#### Разбор на примере

Структура ролика NEURA: 0–3 сек — самый сильный клип (крупный план, неон, движение) держит
внимание с первого кадра; 3–12 сек — развитие (что даёт курс, ключевые визуалы); 12–18 сек —
акцент на результате (сайт/видео/3D — три конкретных навыка); 18–20 сек — призыв к действию,
логотип. Тот же принцип «сильное начало → развитие → акцент → призыв», что и в структуре
лендинга из урока 5 — только на шкале секунд, а не блоков страницы.

#### Действие

1. Тайминг под платформу: короткие форматы требуют более быстрой смены планов, чем горизонтальное
   видео.
2. Переходы: резкая склейка чаще уместнее плавного перехода; количество эффектных переходов
   держим минимальным.
3. Сборка по структуре завязка → развитие → акцент → концовка с призывом.
4. Проверка ритма пересмотром черновика без звука — темп должен держаться сам по себе.

**Типичная ошибка:** ставить самый слабый клип в начало — первые секунды решают, досмотрят ли до
конца.

→ **Результат:** смонтированный черновой ролик.

### Урок 18. Озвучка и субтитры

**Цель:** ролик со звуком без «роботизированного» эффекта и субтитрами, читаемыми на маленьком
экране.

#### Действие

1. Выбор AI-голоса под тон проекта, работа с паузами и интонацией через разметку текста, не
   только сырой текст.
2. Синхронизация озвучки с видеорядом — длина клипов подгоняется под реплики, не наоборот.
3. Автоматические субтитры и ручная доводка: разбивка по смыслу, проверка на ошибки распознавания
   (для ролика NEURA — термины вроде «нейросети», «3D-анимация» часто распознаются некорректно и
   требуют ручной правки).
4. Оформление субтитров под просмотр без звука — размер и контраст, актуально для большинства
   соцсетей.

**Типичная ошибка:** публикация автоматических субтитров без вычитки — ошибки распознавания
терминов снижают доверие к ролику.

→ **Результат:** ролик со звуком и субтитрами.

### Урок 19. Форматы: вертикаль / горизонталь / квадрат

**Цель:** один ролик работает на всех площадках без пересъёмки — только грамотное кадрирование.

#### Действие

1. Форматы под площадки: вертикаль (Shorts/Reels/TikTok) — основной для ролика NEURA, горизонталь
   (YouTube), квадрат (универсальный для лент).
2. Безопасные зоны: интерфейсные элементы площадки (кнопки, подписи) — ключевое действие и текст
   держатся вне этих зон.
3. Перекадрирование без потери смысла: если ключевой объект не помещается при смене пропорций —
   дозаполнение фона нейросетью, не простое растягивание кадра.
4. Финальная сверка всех трёх версий рядом — сохраняется ли смысл и темп в каждом формате.

**Типичная ошибка:** растягивать/сжимать кадр под новый формат вместо перекадрирования —
искажаются пропорции.

→ **Результат:** 3 версии одного ролика под разные форматы.

**Промежуточный итог:** готовый озвученный ролик в 3 форматах.

## Этап 5. 3D-сцены и анимация (уроки 20–23)

Объёмный ролик без опыта в 3D-редакторах. Рабочий пример — 3D-объект бренда NEURA: объёмная
неоновая геометрическая форма (в духе логотипа/акцентного элемента сайта), которую можно
использовать как заставку к ролику из этапа 4 или как самостоятельный визуал. Мудборд уроков
10–14 и файлы этого этапа удобно держать в том же Project (или отдельном — по аналогии с этапом
видео), подключённом к коннектору Google Drive из урока 1.

### Урок 20. От изображения к 3D

**Цель:** получить 3D-геометрию из изображения/текста через нейросеть, не открывая пока 3D-редактор.

#### Действие

1. Обзор image-to-3D сервисов: вход (одно изображение / несколько ракурсов / текст), выход
   (формат геометрии, наличие текстуры).
2. Подготовка исходного изображения: чистый фон и чёткий силуэт объекта — для NEURA это, например,
   изображение геометрической формы на сплошном тёмном фоне без лишних деталей — дают заметно
   более чистую геометрию, чем сложная сцена целиком.
3. Практика: перевод объекта из мудборда уроков 10–14 в 3D, проверка на дефекты геометрии (дыры,
   слипшиеся части).
4. Экспорт в формат, совместимый с Blender (следующий урок).

**Типичная ошибка:** конвертировать в 3D сразу сложную сцену целиком вместо объекта за объектом.

→ **Результат:** 3D-объект, готовый к сборке в сцену.

### Урок 21. Blender: необходимый минимум

**Цель:** набор навыков, достаточный для сборки готовой геометрии в сцену — не освоение
редактора целиком.

#### Действие

1. Интерфейс по минимуму: навигация по вьюпорту, импорт объекта из урока 20, работа со списком
   объектов сцены.
2. Расстановка объектов: позиция, масштаб, поворот — сборка сцены из нескольких объектов в единую
   композицию (для примера NEURA — объект в центре, лёгкий фоновый план).
3. Базовый свет: один-два источника — по тем же принципам света из урока 11, перенесённым в 3D
   (для примера NEURA — холодный неоновый свет сбоку, как в фирменной палитре сайта).
4. Простой фон/окружение, согласованный со стилем мудборда, без лишней сложности.

**Типичная ошибка:** настройка сложного многоисточникового света сразу — для учебной сцены
достаточно двух хорошо поставленных источников.

→ **Результат:** собранная 3D-сцена.

### Урок 22. Камера и движение

**Цель:** оживить сцену — облёт камеры и лёгкое движение создают ощущение объёма.

#### Действие

1. Постановка камеры: ракурс, фокусное расстояние — принципы урока 11, с поправкой на то, что
   камера в движении.
2. Анимация облёта: простая траектория вокруг объекта, минимум ключевых кадров, без сложной
   кривой движения.
3. Лёгкое движение объекта (вращение, парение) для ощущения жизни в кадре — для примера NEURA
   это медленное вращение объекта вокруг своей оси.
4. Проверка ощущения глубины черновым прогоном — считывается ли объём, не выглядит ли сцена
   плоской декорацией.

**Типичная ошибка:** слишком быстрое или дёрганое движение камеры — глазу нужно время прочитать
сцену.

→ **Результат:** черновая анимация сцены.

### Урок 23. Рендер и экспорт

**Цель:** готовый 3D-ролик за разумное время.

#### Действие

1. Настройки рендера под баланс качество/время — какие параметры сильнее всего влияют на время
   рендера, какие можно снизить без потери видимого качества на маленьком экране.
2. Пробный рендер короткого фрагмента перед полным — экономит часы при обнаружении ошибки.
3. Экспорт в формат под монтаж (совместимый с уроком 17, если объект встраивается в ролик) или
   под прямую публикацию.
4. Финальная проверка на разных экранах — на 3D особенно заметна разница в восприятии деталей.

**Типичная ошибка:** запуск полного рендера в максимальном качестве без пробного фрагмента —
ошибка обнаруживается слишком поздно.

→ **Результат:** готовый 3D-ролик.

**Итог этапа «Видео и 3D» (тариф «Видео и 3D», уроки 10–23):** мудборд + озвученное видео в 3
форматах + 3D-ролик + пресеты и промпты уроков 10–23.

## Этап 6. Упаковка под площадки (уроки 24–28)

Превращение готового контента в системную публикацию, которая приносит доход. Доступен только в
тарифе «Всё вместе». Рабочий пример — упаковка ролика NEURA из уроков 15–19 под реальный выход
на площадки: обложка, заголовок, описание, контент-план.

### Урок 24. Форматы и требования площадок

**Цель:** знать требования площадок заранее, а не выяснять их через отклонённую публикацию.

#### Действие

1. Свод по площадкам: YouTube/Shorts, Instagram/Reels, TikTok, Telegram, рекламные кабинеты —
   длина ролика, соотношение сторон, ограничения по контенту.
2. Разграничение требований «формата» (что примет площадка) и требований «алгоритма» (что она
   продвигает) — смешение этих двух вещей — частая ошибка.
3. Сверка готового ролика NEURA (три формата из урока 19) с требованиями конкретных приоритетных
   площадок.
4. Личный чек-лист под 2–3 приоритетные площадки — не все сразу.

**Типичная ошибка:** публикация одинакового контента без адаптации сразу на все площадки.

→ **Результат:** чек-лист форматов под площадки.

### Урок 25. Обложки и превью

**Цель:** обложка, по которой кликают — не просто эстетичная картинка, а инструмент с понятной
механикой.

#### Действие

1. Принципы кликабельной обложки: контраст, один фокус внимания, читаемость на размере превью
   в ленте.
2. Генерация вариантов на основе мудборда NEURA (урок 14) — обложка узнаваема как часть проекта
   по палитре и стилю с первого взгляда.
3. Три подхода к одной обложке (акцент на объект/визуал, на текст-оффер, на цифру/результат)
   вместо одного варианта на глаз — для ролика NEURA, например: неоновый объект крупным планом,
   текст «Сайты. Видео. 3D.», и вариант с акцентом на цену/скидку.
4. Проверка обложки в реальном размере превью, не в полный экран.

**Типичная ошибка:** перегрузка обложки текстом — на превью читается максимум 3–5 слов.

→ **Результат:** 3 варианта обложки для ролика.

### Урок 26. Заголовки, описания, теги

**Цель:** текстовая упаковка, реально увеличивающая охват, не формальное заполнение полей.

#### Действие

1. Формула заголовка: конкретика/интрига + польза, без кликбейта, не подтверждённого содержанием
   ролика — для NEURA, например: «Как за один курс собрать сайт, видео и 3D-ролик без кода» —
   конкретный результат, не «секрет, который скрывают».
2. Несколько вариантов заголовка/описания через Claude по брифу проекта — сравнение и выбор, не
   первый сгенерированный вариант. Skill «голос бренда» из урока 6, подключённый к текущему
   Project, держит формулировки в одном тоне с сайтом и роликом без повторной настройки.
3. Базовые принципы SEO для видео и сайта: естественное размещение ключевых слов, без спам-списка.
4. Структура описания: первая строка держит интерес (видна до «показать полностью»), дальше —
   детали и ссылка на сайт/тариф.

**Типичная ошибка:** заголовок обещает больше, чем есть в ролике — краткосрочный клик ценой
доверия и будущих просмотров.

→ **Результат:** пакет заголовков/описаний для ролика и сайта NEURA.

### Урок 27. Контент-план и регулярность

**Цель:** превратить разовые проекты уроков 5–23 в систему публикаций — регулярность растит
охваты сильнее одного вирусного ролика.

#### Действие

1. Механика без завышенных обещаний: алгоритмы отдают охваты тем, кто публикуется часто и
   предсказуемо.
2. Инвентаризация наработанного на уроках 5–23 (сайт NEURA, изображения мудборда, видео,
   3D-объект) — источник нескольких публикаций, а не только одного финального ролика.
3. Контент-план на 2 недели: тема, формат, площадка, дата на каждую единицу контента — удобно
   вести в Google Docs/Sheets через коннектор из урока 1, чтобы Claude мог дополнять план прямо
   по команде в чате, без пересылки файла туда-обратно.
4. Устойчивый темп — реалистичная частота, которую можно держать долго, без спринта на неделю с
   последующим выгоранием.

**Типичная ошибка:** планировать частоту «как у крупных блогеров» без учёта своего реального
времени на производство.

→ **Результат:** контент-план на 2 недели вперёд.

### Урок 28. Монетизация и первые деньги

**Цель:** реальные, проверяемые каналы дохода — без заявленных цифр, которых нет ни у одного
честного курса на рынке.

#### Действие

1. Партнёрские программы площадок (YouTube, Instagram, TikTok): реальные условия входа (пороги
   по подписчикам/просмотрам), без завышенных ожиданий по срокам.
2. Приём заказов на сайты/видео/3D со стороны — портфолио уроков 5–23 (в том числе сам факт
   участия в производстве материалов NEURA) как доказательство навыка.
3. Расчёт цены первого платного проекта: время, сложность, стоимость самих нейросетей (урок 1)
   — чтобы не уйти в минус.
4. Ведение первого клиента: бриф → правки → сдача — тот же процесс, что уже пройден на себе на
   уроках 5–9, только с заказчиком на другой стороне.

**Типичная ошибка:** называть клиенту цену без учёта собственных расходов на подписки нейросетей.

→ **Результат:** коммерческое предложение (прайс + портфолио-питч) для первых клиентов.

**Итог курса (тариф «Всё вместе», уроки 1–28):** сайт + видео + 3D-ролик + обложки/тексты под
все площадки + контент-план + база промптов по всем 28 урокам.
