# Настройка личного кабинета (Supabase)

Всё, что происходит на самом сайте (регистрация, вход, личный кабинет), уже готово и лежит в
[supabase-config.js](../supabase-config.js), [auth.js](../auth.js), [cabinet.js](../cabinet.js),
[payment.js](../payment.js). Ниже — что нужно сделать один раз в самом Supabase, чтобы это заработало.

## 1. Создать проект

1. Зарегистрироваться на [supabase.com](https://supabase.com) (бесплатно, свой аккаунт — этот шаг только вручную).
2. Создать новый проект (New project), выбрать любой регион.
3. Зайти в **Settings → API** — там будут `Project URL` и `anon public` ключ.
4. Вставить их в [supabase-config.js](../supabase-config.js):
   ```js
   const SUPABASE_URL = 'https://xxxxx.supabase.co';
   const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```
   Это публичные значения, их можно спокойно хранить в открытом коде сайта на GitHub — это не пароль.

После этого шага регистрация/вход/личный кабинет на сайте уже заработают (без оплаты пока).

## 2. Создать таблицу purchases

В Supabase → **SQL Editor** — вставить и выполнить содержимое [schema.sql](schema.sql).

## 3. Настоящий таймер акции -50% (не сбрасывается по IP)

Без этого шага таймер на сайте всё равно работает (см. `script.js`), но хранит дедлайн только
в `localStorage` браузера — значит, переживает обновление страницы, но не переживает смену
браузера/устройства или инкогнито с того же IP. Чтобы дедлайн был действительно привязан к IP
и хранился на сервере:

1. Выполнить [schema.sql](schema.sql) ещё раз (или отдельно — там теперь есть и таблица
   `promo_windows`), если ещё не выполняли после этого обновления.
2. Скопировать папку `promo-timer` в `supabase/functions/promo-timer` в проекте.
3. Задеплоить:
   ```
   supabase functions deploy promo-timer --no-verify-jwt
   ```

Дополнительных секретов не нужно. После деплоя сайт сам начнёт дёргать эту функцию
(адрес собирается из `SUPABASE_URL`, который уже указан в `supabase-config.js`) и получать
дедлайн, привязанный к IP посетителя, — обновление страницы или повторный заход с того же IP
дальше не трогают отсчёт.

## 4. Оплата — сейчас через WhatsApp, автоматический приём Kaspi можно подключить позже

Владелец решил не ждать одобрения заявки на Kaspi Webpay и запускать продажи сразу через
ручную схему: клиент оформляет заявку на сайте → его перекидывает в WhatsApp с номером
заказа → владелец вручную высылает реквизиты/QR Kaspi и после оплаты открывает доступ
(шаг 5 ниже). Раздел 4.2 — рабочий способ на сейчас. Раздел 4.3 (полная автоматизация приёма
платежей самим Kaspi) можно подключить в любой момент позже, без переделки остального.

### 4.1. Номер WhatsApp

1. В Vercel → Project → Settings → Environment Variables добавить `IP_WHATSAPP` — номер в
   формате для wa.me: только цифры, с кодом страны, без `+` и пробелов (например `77081234567`).
2. Пересобрать деплой (или дождаться следующего пуша — build-legal.js подставит номер в
   [whatsapp-config.js](../whatsapp-config.js) при каждой сборке, тем же способом, что и
   реквизиты в оферте).
3. Пока переменная не задана — кнопка оплаты на сайте показывает «Оплата скоро подключится»
   и никуда не ведёт (см. `WHATSAPP_CONFIGURED` в `whatsapp-config.js`).

Готово — с этого момента оплата на сайте уже работает по ручной схеме (см. пункт 5).

### 4.2. (Позже, необязательно) Заявка в Kaspi на автоматический приём

1. Подать заявку на [kaspi.kz/webpay/partnership](https://kaspi.kz/webpay/partnership).
   Нужен действующий ИП/ТОО и счёт в Kaspi — они уже есть.
2. Kaspi проверяет сайт на соответствие требованиям партнёрской программы: рабочий сайт,
   публичная оферта, политика конфиденциальности, реквизиты продавца, описание услуги и цены.
   **Всё это на сайте уже есть** (`oferta.html`, `privacy.html`, блок тарифов).
3. После одобрения Kaspi выдаёт: доступ в кабинет Kaspi Pay, секрет для вебхука и
   **документацию с точной спецификацией** — как называются поля, каким алгоритмом
   считается подпись, что вернуть в ответе.

### 4.3. (Позже) Вставить платёжные ссылки и включить автоматику

Когда заявка одобрена и нужно перейти с ручной схемы на автоматическую: в кабинете Kaspi Pay
создать платёжную ссылку под каждый тариф (суммы — в `plans-data.js`), вставить их в
`KASPI_LINKS` в [plans-data.js](../plans-data.js), сверить `KASPI_ORDER_PARAM`, и в
[payment.js](../payment.js) заменить редирект на `wa.me` обратно на редирект по `KASPI_LINKS`
(старый код — в истории git). Дальше — дописать вебхук:

> ⚠️ Функция [kaspi-webhook](kaspi-webhook/index.ts) намеренно **не дописана**: проверка
> подписи возвращает `false`, пока не реализована по документации Kaspi. Без рабочей
> проверки подписи кто угодно смог бы пометить заказ оплаченным и забрать курс бесплатно.
> Все места помечены `TODO(kaspi)`.

1. Реализовать `verifySignature()` по документации Kaspi, сверить имена полей и формат ответа.
2. Скопировать папку `kaspi-webhook` в `supabase/functions/kaspi-webhook`.
3. Задать секрет из кабинета Kaspi:
   ```
   supabase secrets set KASPI_WEBHOOK_SECRET=выданный_секрет
   ```
4. Задеплоить:
   ```
   supabase functions deploy kaspi-webhook --no-verify-jwt
   ```
5. Скопировать URL функции (вида `https://xxxxx.supabase.co/functions/v1/kaspi-webhook`)
   и указать его в кабинете Kaspi как адрес уведомлений об оплате.
6. **Обязательно проверить на реальном тестовом платеже** (можно на минимальную сумму),
   что заказ помечается оплаченным и доступ открывается.

Пока `KASPI_WEBHOOK_SECRET` не задан, функция отвечает 503 и ничего в базе не меняет —
защита от случайного деплоя в незавершённом виде.

## 5. Как отмечать оплату (сейчас — основной способ, не временный)

Заявка приходит в WhatsApp с номером заказа, тарифом, суммой и email покупателя. После того
как деньги пришли на Kaspi: зайти в Supabase → **Table Editor → purchases**, найти строку по
`invoice_id` (он же номер заказа из сообщения в WhatsApp) и поменять `status` с `pending` на
`paid` — доступ в кабинете покупателя откроется сразу, без перезахода.

Если позже подключится автоматический вебхук (пункт 4.3) — этот шаг станет не нужен, но код
никак не изменится: `purchases.status = 'paid'` — это единственное, на что реагирует кабинет,
неважно, кто его выставил, скрипт или человек.

## Важно про безопасность

- В `supabase-config.js` (публичный код сайта) — только `anon key`, это нормально и безопасно.
- `KASPI_WEBHOOK_SECRET` и `service_role key` **никогда** не должны попадать в файлы сайта или
  в публичный GitHub-репозиторий — они живут только как секреты внутри Supabase Edge Function.
- Номер WhatsApp — тоже личные данные владельца: в `whatsapp-config.js` (публичный код на
  GitHub) остаётся только токен `__IP_WHATSAPP__`, реальный номер живёт как переменная
  окружения `IP_WHATSAPP` в Vercel и подставляется при сборке — тем же способом, что и
  телефон/адрес/реквизиты в `oferta.html`/`privacy.html`.
